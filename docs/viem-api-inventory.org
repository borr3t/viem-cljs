* About this document
This is the verified inventory of the viem surface that viem-cljs wraps. It is research
only; implementation happens in phases 2–4 (section 11 is the outline).

*Product constraint that shapes everything below:* viem-cljs is a COMPLETE wrapper of
viem's main surface (clients, transports, chains, actions, accounts, contracts,
utilities, event watchers) written as ClojureScript only: no =^js= hints, no JavaScript
interop at call sites (all viem interop confined to =viem-cljs.util= and
=viem-cljs.binding=), kebab-case keyword maps in and out, promesa promises for every
read/call, core.async channels for watchers. The only runtime npm dependency is =viem=.

** Method and evidence tags
Every fact carries one or more evidence tags:
- =[DTS]= — read from the installed package's type declarations,
  =node_modules/viem/_types/**/*.d.ts= (viem *2.56.9*, installed 2026-09-25 by
  =npm install=; =package.json= =exports= map, 27 subpaths). Parameter names, option
  keys, return types and error class names come from here. Export *names* were
  additionally enumerated at runtime (=Object.keys(require("viem/<subpath>"))=) so
  every name in a census table exists in the installed CJS build.
- =[RUN]= — observed by running the installed package in Node 22.23.2 during this
  session: a =custom= transport over an in-memory =request= stub (no network), the ABI
  codecs, unit/address/hash utilities, account factories with a *fresh random key that
  was generated in-process and discarded* (never printed, never written).
- =[DOC]= — from https://viem.sh (pages listed in section 14), used for semantics only.
Anything not covered by these tags is in section 12 "Pitfalls and uncertainties".

** Reading conventions
- viem names are given verbatim (camelCase); the kebab-case keyword translation lives in
  section 11.2. A "quantity" is a JavaScript =bigint= on the viem side; an "index" is a
  JavaScript =number=; =Hex= / =Hash= / =Address= are =0x=-prefixed strings.
- "Tier" column values (section 10): =1= complete wrap in phases 2–4, =2= wrap later or
  partially, =3= not wrapped (with the reason).
- The CLJS names proposed in tables are the section-11 proposal, not yet code.

** 2.3 The actions pattern [DOC clients/intro][DOC clients/custom][RUN]
Two equivalent call shapes exist:
1. *Decorated client*: =client.getBlock(args)= — =createPublicClient= applies
   =publicActions=, =createWalletClient= applies =walletActions=, =createTestClient=
   applies =testActions({mode})=; =client.extend(decorator)= adds more (e.g.
   =createClient(...).extend(publicActions).extend(walletActions)=).
2. *Tree-shakable*: =import { getBlock } from 'viem/actions'; getBlock(client, args)= —
   the same function; the decorator merely binds =client= as the first argument
   (=publicActions(client)= returns an object of closures) [RUN: 63 keys].
viem-cljs wraps shape 2 (section 11.1): one CLJS fn per action, client as first
argument, works on ANY client (bare, public, wallet, test) — the decorated methods are
sugar and are Tier 3.

** 2.4 =client.request= [DTS]
=client.request({method, params}, options?)= is the EIP-1193 request fn of the transport,
typed by =rpcSchema= (=EIP1474Methods= by default, test methods for test clients). Wrapped
as the raw escape hatch =core/request!= (Tier 1).

** 8.2 core.async mapping (APPROVED 2026-09-25, section 11.1 =viem-cljs.events=)
- Each =watch-*!= fn returns ONE core.async channel. Values are tagged maps, one event per
  put: ={:event :block-number :block-number 100N :prev 99N}=, ={:event :block :block {...}}=,
  ={:event :block-header :header {...}}=, ={:event :log :log {...}}= (viem's =onLogs= batch of
  n logs → n puts, in order), ={:event :pending-transaction :hash "0x…"}= (batch → n puts),
  ={:event :error :error <ex-info>}= (channel stays open — mirrors viem).
- Unsubscribe = =(events/stop! ch)=: calls viem's =unwatch= and closes the channel. Closing
  the channel from the consumer side also unsubscribes: the producer uses =put!= with a
  callback and, on the first =false= return (channel closed), calls =unwatch= (so
  =(async/close! ch)= is enough).
- Buffering: default =(async/chan 1024)=, overridable with =:buf= (any buffer / number). A
  dropping or sliding buffer is the caller's choice for high-volume log streams
  (uncertainty 12.4).
- =:poll?=, =:polling-interval=, =:emit-on-begin?=, =:emit-missed?=, =:batch?= pass

** 11.2 Option translation (CLJS map → viem object), rules
1. Keys: =kebab->camel= mechanically (=:max-fee-per-gas= → =maxFeePerGas=, =:block-tag= →
   =blockTag=, =:from-block= → =fromBlock=). String keys pass through verbatim (the escape
   hatch for Solidity struct fields with unusual casing).
2. Boolean options written with =?= (=:strict? :poll? :emit-on-begin? :include-transactions?
   :allow-failure? :deployless? :batch?=) have the =?= stripped before camelling
   (=:strict?= → =strict=). Both spellings accepted.
3. Keyword values → strings via =enum-value= (=:latest= → ="latest"=, =:eip1559= →
   ="eip1559"=, =:success=). Applies to =block-tag=, =type=, =state-mutability=,
   =mode=, =dir=, =to= (=:hex :bytes :bigint :number :string :boolean=).
4. Quantities: any key in the *quantity set* (=value gas gas-price max-fee-per-gas
   max-priority-fee-per-gas max-fee-per-blob-gas block-number from-block to-block (when
   not a tag keyword) base-fee-per-gas gas-limit timestamp balance amount=) is coerced with
   =util/->bigint= (BigInt | safe integer | decimal string | =0x= string). Everything else is
   passed as-is (viem's =index= slots =nonce chain-id block-count confirmations
   polling-interval timeout seconds interval account-index address-index= are JS numbers).
5. =:chain= accepts a keyword (=:mainnet=), a chain id, a kebab map (=define-chain=
   output or =chain->map= data), or an already-built chain object — resolved by
   =chains/chain=. =:account= accepts an account object from =accounts=, an address
   string, or a kebab map ={:address ..}= (json-rpc account).
6. =:abi= accepts a vector of human-readable strings (auto =parseAbi=) or a JSON ABI as
   kebab maps (mechanical translation) or a JS ABI array.
7. =:args= is a vector; nested maps (structs) are translated with rule 1; BigInt/number/hex
   values untouched (viem accepts JS numbers for =uintN= [RUN]).
8. =nil= values are dropped; sets become arrays; functions (callbacks, custom signers)
   pass through.
9. Watcher callbacks are never exposed: =events= supplies them and feeds the channel.
** 11.3 Result translation (viem value → CLJS), rules and value types
1. Plain objects/arrays → kebab keyword maps / vectors (=->clj=), recursively; keys only —
   values are never re-cased (hex strings, ="latest"=, ="success"= stay strings).
2. *BigInt stays BigInt* (DECIDED 2026-09-25, uncertainty 12.1): every wei-denominated
   amount arrives and leaves as an opaque, exact BigInt; CLJS arithmetic on them goes
   through the provided helpers only (=utils/big=, =utils/add=, =utils/sub=, =utils/mul=,
   =utils/div=, =utils/cmp=, =utils/format-units= …) — never =+ - inc dec= on mixed types. =value gas gasPrice
   maxFeePerGas maxPriorityFeePerGas maxFeePerBlobGas blockNumber timestamp gasLimit gasUsed
   cumulativeGasUsed effectiveGasPrice baseFeePerGas difficulty totalDifficulty size
   blobGasUsed excessBlobGas blobGasPrice v oldestBlock= and every =uintN=/=intN= ABI value
   arrive as JS BigInt; =nonce transactionIndex logIndex yParity chainId= and =getChainId=
   / =getTransactionCount= / =getBlockTransactionCount= are JS numbers; =status= is
   ="success"= / ="reverted"= (string, not keyword); =type= is ="eip1559"= etc.
   =viem-cljs.util= makes BigInt hashable and prints it as =1000N=.
3. Decoded ABI values: single output → bare value; multiple outputs → vector; named struct
   → kebab map; unnamed event params → vector (=args=) [RUN section 4.2].
4. Chain objects are not converted unless asked (=chains/chain->map=); account objects are
   projected with =account->map= (=:address :type :source=) — never their signer closures
   or key material.
5. =Uint8Array= (bytes) values pass through untouched; =:to :bytes= variants exist on the
   codec fns for callers who want them.
6. Errors: section 9.5.

* 12. Pitfalls and numbered uncertainties
1. *BigInt house position.* viem returns JS BigInt for every quantity; CLJS numbers are
   doubles (53-bit) so converting would silently corrupt wei amounts and =uint256= values.
   RECOMMENDED (and implemented in =util=): keep BigInt end to end; accept BigInt / safe
   integer / decimal string / hex string on input via =->bigint=; =bigint->number= returns
   nil instead of losing precision; =utils/format-units= for display. Consequence to
   document: =(+ 1 x)= throws (=TypeError: cannot mix BigInt=) — use BigInt literals on both
   sides (=(js/BigInt 1)= or a =utils/big= helper); =inc=/=dec= don't work on BigInt.
   Alternative (decimal strings everywhere, as in openrouter-cljs prices) rejected:
   arithmetic and comparisons on BigInt are native and exact.
   DECIDED 2026-09-25 (Parley): YES — BigInt in/out, helpers-only arithmetic (11.3).
2. *Function naming.* Proposal: viem names kebab-cased 1:1 with =!= on I/O
   (=get-balance!=). Alternative: drop the =get-= prefix (=balance!=). The 1:1 rule keeps
   viem.sh directly usable as documentation.
   DECIDED 2026-09-25 (Parley): YES — =!= iff the fn can hit the network or move chain
   state; pure/local fns (format/parse, checksums, address tests, encode/decode) no =!=.
3. *Chain registry exposure.* 737 objects, 87 with functions inside, all with an =extend=
   closure: not convertible to pure data losslessly. RECOMMENDED: keep JS chain objects
   opaque behind =chains/chain= (keyword/id lookup, lazily) and offer =chain->map= for
   inspection; =define-chain= takes a kebab map. Eagerly converting all 737 at load is
   avoidable. Aliases (28 names sharing an id, e.g. =:foundry :anvil :hardhat= = 31337)
   make =by-id= ambiguous — return the first name in registry order and document.
   Open (implementation detail; the recommendation stands unless Parley objects).
4. *Watcher backpressure.* viem invokes =onLogs= synchronously with batches; the channel
   producer uses =put!= with a callback. With the default 1024 buffer, a slow consumer on
   a busy mainnet log stream will fill it; core.async then queues pending puts up to 1024
   and throws beyond. Options: (a) default =(async/chan 1024)= + documented =:buf=
   (sliding/dropping) — RECOMMENDED; (b) pause the watcher (unwatch/rewatch) when full —
   complex. Verify in phase 4 with a synthetic burst test. Channel contract (one event
   per put, close on unsubscribe) APPROVED 2026-09-25.
5. *Polling vs subscription.* viem chooses =eth_subscribe= automatically for webSocket/ipc
   transports and polling for http; =:poll? true= forces polling on sockets;
   =watch-block-headers!= is socket-only. The channel API is identical either way; the
   difference is latency and RPC cost. No wrapper decision needed beyond pass-through.
6. *Struct field re-casing.* =camel->kebab= lowers a LEADING capital without a dash
   (=Owner= → =:owner=), so a Solidity struct field starting with a capital cannot be
   round-tripped through keyword keys. Escape hatch: string keys pass through verbatim in
   =->js=. Consecutive capitals (=tokenURI= → =:token-u-r-i=) round-trip but read oddly.
   Decide whether =args= subtrees should skip re-casing entirely (then event =args= from
   =decode-event-log= would keep camelCase keys — inconsistent with the rest). RECOMMENDED:
   re-case (consistency), document the escape hatch.
7. *=formatAbi= is not in viem.* Only =formatAbiItem= (per item). Wrapper offers
   =format-abi= = =(mapv format-abi-item abi)=; confirm this is enough.
8. *=getContract= Proxies.* Members are Proxies whose keys are unknowable
   (=Object.keys= empty); wrapping them would require interop at call sites. Replaced by
   =contract/get-contract= + explicit fns. APPROVED 2026-09-25 (bound contract map,
   actions called through it).
9. *Non-BaseError throws.* ox (=Value.InvalidDecimalNumberError=), abitype
   (=UnknownSignatureError=), plain =Error=/=SyntaxError= from =parseSignature= /
   =hexToNumber=. =util/viem-error= wraps them generically (=:name= from =name=); whether to
   strip the ox =Value.= prefix in =:name= is open. RECOMMENDED: keep verbatim.
10. *=http()= without URL and without chain throws synchronously* in =createClient=
    (=UrlRequiredError=) [RUN]; with a chain it silently uses the chain's public default
    RPC (mainnet: =https://ethereum.reth.rs/rpc=). The wrapper should reject
    =:viem-cljs/config-error= early and document the public-RPC rate limits.
11. *Sync action variants* (=sendTransactionSync=, =writeContractSync=,
    =sendRawTransactionSync=, =sendCallsSync=) depend on =eth_sendRawTransactionSync=
    (EIP-7966) node support; anvil ≥ 1.x reportedly supports it, most public RPCs do not.
    Wrap (Tier 1) but smoke only on anvil; expect =MethodNotSupportedRpcError= elsewhere.
12. *Multicall batching on clients* (=:batch {:multicall true}=) turns concurrent
    =read-contract!= / =call!= into Multicall3 aggregations; requires
    =chain.contracts.multicall3= (or =deployless=) — a client on a custom chain without
    it fails with =ChainDoesNotSupportContract= only when batching triggers. Document.
13. *Node version.* No =engines= field; viem needs global =fetch= (Node ≥ 18) and uses
    =isows=/=ws= for sockets. Tested here on Node 22.23.2; Node 18 is EOL — recommend
    documenting Node ≥ 20.
14. *Keystore JSON (=localAccountJson=).* Not in viem's surface; ox (viem's dependency)
    has =ox/Keystore= but viem does not re-export it. DECIDED 2026-09-25 (Parley): YES,
    add =account-from-keystore!= — implemented with Node =crypto= + viem =keccak256= /
    =privateKeyToAccount= (section 5.3), =ox/Keystore= as fallback. Remaining risk:
    ciphers other than =aes-128-ctr= or =prf= other than =hmac-sha256= are rejected with
    =:viem-cljs/argument-error= (the v3 spec allows nothing else in practice).
15. *EIP-1193 provider accounts vs local accounts.* In Node there is no injected
    provider; wallet actions with a json-rpc account (=:account "0x…"=) need a transport
    whose node can sign (anvil unlocked/impersonated accounts) — the phase-5 smoke covers
    both paths (local account → =eth_sendRawTransaction=; impersonated address →
    =eth_sendTransaction=). Browser wallets are out of scope for tests.
16. *Gas estimation edge cases.* =estimateGas= / =simulateContract= reject with
    =EstimateGasExecutionError= / =ContractFunctionExecutionError= whose root is a
    node-message-classified error (=InsufficientFundsError=, =ExecutionRevertedError=,
    =IntrinsicGasTooLowError= …); the classification depends on the node's error strings
    (=UnknownNodeError= otherwise). =prepareTransactionRequest= fills =gas= via
    =estimateGas= unless given; on chains with L1 data fees (OP Stack) the estimate excludes
    the L1 fee (use =viem/op-stack= =estimateTotalFee=, Tier 2).
17. *=client.token= / =tokens=.* New in 2.5x (=createPublicClient= gained a =token= key
    and a =tokens= config); semantics for non-Tempo chains not verified. Tier 2.
18. *anvil availability for the smoke.* DECIDED 2026-09-25 (Parley): anvil is installed
    at =/home/borret/.foundry/bin/anvil= (v1.8.1 verified); the phase-5 smoke spawns it as
    a subprocess directly — no anvil npm package. Fallback when the binary is missing:
    read-only public-RPC sections only, wallet/test sections reported SKIPPED.
19. *=localStorage= / =memory= transports.* DECIDED 2026-09-25: not in viem, not invented;
    in-memory = =custom= transport (covered), localStorage = out of scope (section 2.2).
